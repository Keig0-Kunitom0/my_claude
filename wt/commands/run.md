# /wt:run

任意のプロンプトを、別 worktree に立てた新しいセッションで実行する。
`/wt:issue` と `/wt:review` でカバーされないタスクのための逃げ道。

**引数**: `$ARGUMENTS`

---

## 引数の解釈（最初に行う）

**先にオプションを切り出す。** `$ARGUMENTS` から `--base {ref}` / `--branch {名前}` /
`--name {名前}` を回収し、**残りをプロンプトとして扱う**。

オプションを回収せずに丸ごと投入すると、`--base origin/develop` のような文字列が
プロンプト本文に混ざったまま新セッションに届く。

```
/wt:run "調査して報告して"
/wt:run --base origin/develop "develop 起点で調べて"
/wt:run --branch 1234/hotfix --name hotfix-1234 "この修正をコミットして"
```

プロンプトが空になった場合は `AskUserQuestion` で確認する（空のまま起動しない）。

## 手順は共通スキルにある

`wt-dispatch` スキルを読んで、その手順0〜6に従うこと。
**ここに手順を書き写してはならない。**

| 変数 | 値 |
|---|---|
| `NAME` | `--name <name>` があればそれ。無ければ `wt-<プロンプト先頭の短縮スラッグ>` |
| `BASE_REF` | `--base <ref>` があればそれ。無ければ **`HEAD`**（カレント） |
| `CHECKOUT_MODE` | `--branch <name>` があれば `branch`、無ければ **`detached`** |
| `BOOT_PROMPT` | **引数のプロンプトをそのまま素通しする** |

## プロンプトは加工しない

**投入先のコマンドを詮索しない。** `herdr agent prompt` は文字列を流し込むだけなので、
このコマンドは中身が何であるかを知る必要がない。だから任意のプロンプトが通る。

ただし**投入先が成果物をファイルに書く種類のタスクなら、保存先の絶対パスを
呼び出し元が自分でプロンプトに含めること**。worktree 内に書かれると撤収時に消える
（理由は `wt-dispatch` を参照）。このコマンドは自動では添えない。

## `--branch` を指定するとき

既定は `detached`。**コミットを伴う作業を投げる場合は `--branch` を指定すること。**

detached のままコミットを重ねるとブランチ名が無く、後から辿るのに `git reflog` が要る。
`--branch` を指定すれば最初からブランチ付きで作られる。

```
/wt:run "調査だけして報告して"                          → detached でよい
/wt:run --branch 1234/hotfix "この修正をコミットして"    → ブランチが要る
```

## `NAME` の自動生成

`--name` が無い場合、プロンプト先頭から生成する。`wt-dispatch` の名前制約
（小文字英字始まり・小文字英数と `-` `_` のみ・**32文字以内**）を満たすこと。

生成結果が既存の worktree と衝突する場合は、`wt-dispatch` の手順1が検出して人間に聞く。
**衝突を避けるために勝手に連番を付けない**（同じ作業の再開なのか別の作業なのかを
判断できるのは人間だけ）。

## 定着したらプリセットに昇格させる

このコマンドで繰り返し同じ形を打つようになったら、`/wt:issue` や `/wt:review` と同じく
専用コマンドに切り出す。`wt-dispatch` に手順が集約されているため、追加コストは
**プリセット表4項目を書くだけ**で済む。

## 実行

1. `wt-dispatch` スキルを読む
2. 上表の値を当てて手順0〜6を実行する
3. 手順6の内容を報告する（`workspace_id` を必ず含める）
